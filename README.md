# 矩形板材下料 · 多订单拼版断头切割排料（Panel Nesting）

面向小型手作工坊的矩形板材裁切排样 Web 应用，支持**多张订单混合拼版**：
每张订单填写唯一订单号与零件清单（不同订单允许同名零件），系统按
**订单 → 零件行 → 数量的固定输入顺序**、遵循**断头切割（guillotine cut）**规则
逐板生成裁切方案，落位保留订单归属，并按订单输出跨板取件清单与材料费分摊。
表单还可登记**临时余板库存**：每块余板带唯一编号与实际长宽，已用板找不到落位时
依输入顺序优先耗用余板、最后才开标准新板；结果按各板实际尺寸绘图，并列出余板
已用 / 未用编号，材料费只对新增标准板计费。发现损坏件时，可在分单取件清单中
勾选后一键生成**独立补切方案**（仅重排所选件、独立使用标准新板，原方案落位与
分摊不变、不重复耗用余板库存）。

- 前端：React 18 + Vite
- 后端：Node.js + Express（排料 / 分摊 / 补切算法见 `server/src/cutting.js`）
- 部署：Docker / Docker Compose（镜像内完成依赖安装与前端构建，一键启动）

## 一条命令启动

```bash
docker compose up -d --build
```

该命令会自动完成：安装 npm 依赖 → 构建 React 静态资源 → 启动 Node 服务。

启动后访问：

> **http://localhost:8080**

停止服务：`docker compose down`；查看运行日志：`docker compose logs -f`。

## 本地开发（不使用 Docker）

要求 Node.js ≥ 18。根目录一条命令安装所有 workspace 依赖：

```bash
npm install
```

分别启动后端（8080）与前端开发服务器（5173，已配置 `/api` 代理）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2
```

访问 http://localhost:5173 。

生产方式本地运行（先构建再由 Express 托管）：

```bash
npm run build
npm start             # http://localhost:8080
```

算法自检（面积守恒、刀路几何、多订单归属、最大余数法分摊等）：

```bash
npm test
```

## 使用说明

1. 填写**原板长度、原板宽度、锯缝宽度**以及**每张原板材料价（元）**
   （非负、最多两位小数，可为 0；单位统一即可，长度通常用 mm）。
   **设备最大单刀长度**为选填：留空表示设备不限制单刀长度、沿用全部既有排料规则；
   填写时必须为**正数**（与长度同单位），系统只产出每一刀都不超过该长度的刀路。
2. **（选填）登记临时余板库存**：在「临时余板库存」中逐块录入手边可用的余板，
   每行一块——**唯一编号**（留空按“余板1、余板2…”自动编号，编号不可重复）、
   **长度与宽度均为正数**，尺寸按余板实际情况填写；可随时添加 / 删除行
   （整行留空视为未录入）。不登记余板时行为与旧版完全一致。
3. 在订单清单中为每张订单填写：
   - **唯一订单号**（留空则按“订单1、订单2…”自动编号，订单号不可重复）；
   - 零件行：名称、长度、宽度、数量；**同一订单内零件名不可重复**，
     **不同订单允许使用同名零件**（系统按“订单号 + 零件名”区分）。
   - 可添加 / 删除零件行与订单，或点击「载入示例」（示例含两块演示余板）。
4. 点击「生成多订单裁切方案」。结果区显示：
   - **用板总数、新增标准板数、耗用余板数**、零件总数、零件总面积、
     **锯缝损耗面积**、**余料总面积**、利用率、**材料费合计**（仅计新增标准板），
     以及本次计算所用的**设备最大单刀长度上限**（未填写时显示“不限制”）；
   - **临时余板耗用情况**：分两栏列出**已用余板**（编号、实际尺寸、所在板号，
     注明不收取材料费）与**未用余板**（编号、实际尺寸，退回库存下次再用）；
   - **分单取件清单**：按订单列出每个零件件号、**所在板号**与**坐标 (x,y)**，
     跨板订单以高亮徽标提示所在板号，供分单取件；
   - **订单材料费汇总**：各订单零件数、面积、所在板号与材料费分摊额；
   - 每张板的裁切图——**按该板实际尺寸绘制**（余板尺寸可能不同于标准板；
     余板卡片以绿色边框与「余板编号」徽标标识）——米黄色为余料、彩色块为零件且
     **左上角标注订单号**、灰色锯缝带上的虚线为刀刃，圆形数字徽章即**下刀次序**；
     标准新板给出本板材料费分摊表，余板则提示“本板不计材料费”；
     另有零件落位表（订单、坐标、尺寸、是否旋转）与刀路表（方向、起终点、
     贯穿长度）；设置了单刀上限时，板图下方统计还会给出
     **该板实际最长刀长 / 上限**。
5. 若零件旋转后大于标准新板且所有余板也放不下、订单号 / 余板编号重复、
   余板长宽非正或板价非法，页面会明确报错。
   设置了最大单刀长度时，若某零件在**所有已用板**上都找不到刀长不超限的落位，
   系统会依输入顺序尝试尚未使用且能加工的**余板**，最后才开启**标准新板**；
   余板与新板上两种切法仍都超限时，会报错指出
   **订单、零件名与件号**（并附两种切法所需刀长、已依次尝试过的余板编号供判断），
   且**不会输出任何超限刀路**。
6. **缺件补切**：在「分单取件清单」的「补切」列勾选损坏件
   （按**订单号 + 零件名 + 件号**三元身份区分，跨订单同名零件互不影响），
   点击「生成补切方案」。系统以**当前排料输入**重新计算原方案并校验所选件
   存在且无重复，然后仅将所选件按**原始尺寸**与**原输入顺序**合并重排为
   独立补切方案——补切**独立使用标准新板、不重复耗用临时余板库存**，
   **原方案落位与材料费分摊保持不变**。结果区展示：
   - 补切件数、**新增板数**、**新增材料费**（新增标准板数 × 单板价）；
   - **补切清单**：逐件关联**原板号 → 新板号**，含坐标、尺寸与是否旋转；
   - 补切材料费按订单分摊表（规则同原方案）；
   - 每张补切新板的裁切板图（含**下刀次序**）与落位 / 刀路明细表。
   补切沿用表单中的**设备最大单刀长度**（留空即不限制）；补切新板也无法在
   上限内加工时，同样报错指出订单、零件与件号，不输出超限刀路。

## 切割规则

- 零件**严格按“订单输入顺序 → 订单内零件行顺序 → 数量 N 连续 N 件”**排料，
  不做大小重排；排料过程中不同订单的零件可共用同一张板（拼版）。
- 每件零件允许旋转 90°；余量相同时优先不旋转。
- 用板优先级（见下节[临时余板库存](#临时余板库存选填-remnants)）：
  先在**所有已用板**的可用矩形（含之前已启用的余板余料）中找落位，
  找不到时依输入顺序尝试**尚未使用且能加工的余板**，最后才开启标准新板，
  尽量减少新增标准板（材料）耗用。
- 每件零件落入某个当前可用矩形区域的左上角，需要两刀释放：
  - **竖切优先方案**：先竖切（贯穿该区域全高），再在左侧料块上横切；
  - **横切优先方案**：先横切（贯穿该区域全宽），再在上侧料块上竖切；
  - 自动选择锯缝损耗更小的方案，平局取竖切。
- 每一刀都**贯穿当前所在矩形区域**，锯缝宽度从余料一侧扣除并计入损耗；
  沿板边的修整切若余边不足一条完整锯缝，则按实际余边宽度落刀。
- 零件在某方向恰好占满区域时，该方向不再下刀（因此零件恰好铺满整块余板时
  该落位不产生任何刀，也天然满足任意单刀长度上限）。
- 余料面积 = 该板实际面积 − 零件面积 − 锯缝损耗面积；
  总余料面积按各板（含尺寸不同的余板）实际面积分别计算后求和。

### 临时余板库存（选填 `remnants`）

- 请求可携带 `remnants: [{ id, width, height }]`，每行一块手边可用的余板：
  - **编号唯一**：留空 / 空字符串按“余板1、余板2…”自动编号；编号重复
    （含与自动编号撞名）整体报错；
  - **长度、宽度均必须为正数**，单位与原板一致；尺寸按余板实际情况填写，
    可大于或小于标准新板。
- **每块余板最多使用一次**（“使用”= 因某零件在已用板上找不到落位而被启用、
  开成一张板）；启用后它就进入正常的“已用板”轮换，后续零件会继续优先
  回填其可用余料矩形，不会因同一余板重复开板。未被启用的余板原样列入“未用”。
- 对每件零件，落位查找顺序严格为：
  1. **所有已用板**（标准新板 + 已启用余板）的每个可用矩形，按现有评分选取；
  2. 找不到可行断头切落位时，按 `remnants` **输入顺序**逐块尝试尚未使用的余板，
     取第一块几何可容纳、且存在不超过 `maxCutLength` 的可行切法的余板；
     几何不足或刀长超限的余板**保持未用**并继续尝试下一块；
  3. 余板也都不可行时，最后才开一张**标准新板**。
- 余板与标准新板遵守**完全相同**的锯缝、旋转与单刀长度规则；旋转后只能放入
  余板（放不进标准新板）的零件也允许加工。
- 结果中每张板带 `kind`（`standard` / `remnant`）、余板另带 `remnantId`，
  且 `width` / `height` 为**该板实际尺寸**；板图按实际尺寸绘制，不强行套标准板框。
- **材料费只对新增标准板计费**：余板是既有库存，其板价按 0 处理、
  不参与逐板分摊；订单材料费汇总与总材料费因此只包含标准新板。

### 设备最大单刀长度（选填 `maxCutLength`）

- **留空 / 不传 / 传 `null`**：不限制单刀长度，完全沿用上述排料与评分规则。
- 填写时必须为**正数**；长度单位与原板一致（通常 mm）。
- 对零件的每个候选落位（每张已用板的每个可用矩形区域；已用板均不可行时，
  再依次尝试尚未使用的余板，最后才是标准新板）
  与每个朝向（不旋转 / 旋转 90°），系统分别构造：
  - **竖切优先**切法：记录其中每一刀的实际刀长（竖切刀长 = 贯穿区域高度，
    横切刀长 = 该刀锯缝带宽度）；
  - **横切优先**切法：同理记录每一刀实际刀长（横切刀长 = 贯穿区域宽度）。
- **仅当一种切法中所有刀长均 ≤ 上限时，该切法才可行**；系统只在可行切法之间做选择：
  - 同一落位 + 朝向下两种切法都可行时，沿用现有规则——锯缝损耗更小（余料面积更大）
    的优先，平局取竖切；
  - 落位与朝向之间仍按现有评分（最紧凑区域 → 余料损失最小 → 靠上 → 靠左 →
    已用板优先 → 输入顺序在前的余板优先 → 标准新板 → 不旋转）选取。
- 已用板上没有任何可行落位时，依序尝试**未使用余板**、再**开启标准新板**；
  若几何上能容纳该件的余板与标准新板上两种切法、两种朝向也都超限
  （或零件旋转后仍大于所有板），则整体报错并指出**订单、零件名与件号**
  （错误信息附标准新板各朝向 / 切法所需刀长，以及已依次尝试过的余板编号），
  **不输出任何含超限刀的方案**。

## 缺件补切规则

- 损坏件以**订单号 + 零件名 + 件号**三元身份标识；不同订单的同名零件是不同件。
- 提交补切时，后端以**当前排料输入**重新计算原方案，并校验所选件
  **存在**（订单、零件名、件号均能对上）且**无重复**；任一不满足即整体报错。
- 仅所选件参与补切：按**原始尺寸**（未旋转的输入长 × 宽）与
  **原输入顺序**（订单 → 零件行 → 件号）合并，重排为**独立补切方案**；
  排料、旋转、锯缝与刀序规则与原方案一致；若提交了 `maxCutLength`，
  补切排料同样只选用全部刀长不超过该上限的切法，新板仍无法加工时按同样格式报错。
- **补切独立使用标准新板**：补切排料不读取 / 不消耗请求中的临时余板库存
  （即便原方案用了余板），因此不会出现“补切把库存余板再用一遍”的重复耗用。
- 原方案的落位、用板数（含余板耗用）与材料费分摊**不受补切影响**，原样返回。
- 补切新板按同样的单板价计费：新增材料费 = 新增标准板数 × 单板价，
  并在补切方案内按订单零件面积比例分摊（最大余数法）。
- 补切清单逐件给出：**原板号**（原方案所在板，可能是余板）与
  **新板号**（补切方案所在的标准新板）。

## 材料费分摊规则

- **只有新增标准新板**按固定的**单板材料价**计费；耗用的临时余板是既有库存，
  板价按 0 处理、不收取也不分摊材料费。板价非负、最多两位小数，
  内部统一换算成整数“分”。
- 每张标准新板内部，按**各订单在该板上的零件实际面积占比**分摊该板板价：
  先取各份额的整数分（向下取整），剩余尾差用
  **最大余数法（Hamilton / Largest Remainder）**逐分补入余数最大的订单；
  **余数相同时按订单输入顺序**优先。
- 因此保证：
  - 每板各订单分摊额之和 **严格等于该板板价**（余板为 0）；
  - 各订单跨板汇总之和 **严格等于总材料费（新增标准板数 × 单板价）**。
- 板上没有任何零件落位的订单不参与该板分摊；板价为 0（含全部余板）时
  各订单分摊 0 元。

## API

`POST /api/cut`（多订单拼版）

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 180.00,
  "maxCutLength": 800,
  "orders": [
    {
      "orderNo": "SO-1001",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 8 }
      ]
    },
    {
      "orderNo": "SO-1002",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 4 }
      ]
    }
  ],
  "remnants": [
    { "id": "YB-01", "width": 700, "height": 500 },
    { "id": "YB-02", "width": 450, "height": 300 }
  ]
}
```

- `maxCutLength`（可选）：设备最大单刀长度，必须为**正数**；省略、传 `null` 或
  空字符串均表示**不限制**。设置后只输出每刀刀长均不超过该值的方案，
  全部切法均超限时返回 HTTP 400，错误信息指出订单、零件与件号。
- `remnants`（可选）：临时余板库存，最多 500 块；每项 `id` 为唯一编号
  （留空 / 空字符串自动按“余板N”编号，重复即报错），`width` / `height`
  必须均为正数。省略或传空数组 `[]` 表示不使用余板，行为与旧版一致。

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "boardPrice": 180,
    "maxCutLength": 800,
    "boardsCount": 3,
    "standardBoardsCount": 2,
    "totalMaterialCents": 36000,
    "remnants": {
      "used":   [ { "id": "YB-01", "width": 700, "height": 500, "board": 1 } ],
      "unused": [ { "id": "YB-02", "width": 450, "height": 300 } ]
    },
    "orders": [
      { "order": "SO-1001", "partsCount": 17, "partsArea": 2400000,
        "materialCents": 24411, "boardIndices": [1, 2] }
    ],
    "pickList": [
      { "order": "SO-1001", "items": [
        { "part": "柜门", "index": 1, "board": 1, "x": 0, "y": 0,
          "w": 600, "h": 400, "rotated": false }
      ] }
    ],
    "boards": [
      { "index": 1, "kind": "remnant", "remnantId": "YB-01",
        "width": 700, "height": 500, "longestCut": 500,
        "cost": { "priceCents": 0, "shares": [] },
        "placements": [{ "order": "SO-1001", "part": "柜门", "index": 1, "...": "..." }],
        "cuts": [{ "seq": 1, "type": "v", "x1": 601.5, "...": "..." }] },
      { "index": 2, "kind": "standard",
        "width": 2440, "height": 1220, "longestCut": 800,
        "cost": { "priceCents": 18000, "shares": [
          { "order": "SO-1001", "area": 864000, "ratio": 35.62, "cents": 6411 },
          { "order": "SO-1002", "area": 1562000, "ratio": 64.38, "cents": 11589 }
        ] },
        "placements": [{ "...": "..." }],
        "cuts": [{ "...": "..." }] }
    ]
  }
}
```

- `boardsCount` / `standardBoardsCount`：用板总数与其中新增标准板数；
  耗用余板数见 `remnants.used.length`。
- `totalMaterialCents`：材料费总额（整数分），**只含新增标准板**
  （= `standardBoardsCount × boardPrice`），余板不计费。
- `remnants.used[]` / `remnants.unused[]`：按余板**输入顺序**给出已用 / 未用编号；
  已用项附实际尺寸与所在板号 `board`，未用项附实际尺寸（退回库存）。
- `boards[]`：每张板带 `kind`（`"standard"` / `"remnant"`），余板另带
  `remnantId`；`width` / `height` 为**该板实际尺寸**（绘图应按此尺寸，
  而非统一套用标准板框）；余板 `cost.priceCents` 为 `0`、`shares` 为空。
- `orders[]`：按订单输入顺序的汇总，`materialCents` 为整数分，
  `boardIndices` 为该订单零件落位的板号（升序、去重，含余板板号）。
- `pickList[]`：分单取件清单，件内按板号升序、同板按切割（输入）顺序，
  含件号、板号与坐标。
- `boards[].cost.shares[]`：标准新板逐订单面积占比（`ratio` 百分比）与分摊额（分）。
- `maxCutLength`：本次计算实际使用的单刀上限；未设置时为 `null`。
- `boards[].longestCut`：该板所有刀路中的实际最长刀长（无刀时为 `0`），
  设置上限后必有 `longestCut ≤ maxCutLength`；`boards[].cuts[].length`
  仍为逐刀贯穿长度。

旧版单订单请求（顶层 `parts`、无 `orders` 与 `boardPrice`）仍然兼容，
整体视为单个自动编号订单、板价 0。

成功返回 `{ "ok": true, "result": { ... } }`；零件无法放入标准新板或任何余板、
所有切法均超过 `maxCutLength`、余板编号重复 / 长宽非正或其他输入非法时，
返回 HTTP 400 与 `{ "ok": false, "error": "..." }`。

`POST /api/recut`（缺件补切）

请求体 = 排料输入（同 `/api/cut`，可含 `remnants`）+ `damaged` 损坏件清单
（订单号 + 零件名 + 件号三元身份）。`remnants` 只用于重算 `original` 原方案，
**补切排料本身独立使用标准新板、不耗用任何余板**：

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 180.00,
  "maxCutLength": 800,
  "orders": [
    { "orderNo": "SO-1001", "parts": [{ "name": "柜门", "width": 600, "height": 400, "quantity": 8 }] },
    { "orderNo": "SO-1002", "parts": [{ "name": "柜门", "width": 600, "height": 400, "quantity": 4 }] }
  ],
  "remnants": [
    { "id": "YB-01", "width": 700, "height": 500 }
  ],
  "damaged": [
    { "order": "SO-1001", "part": "柜门", "index": 1 },
    { "order": "SO-1001", "part": "柜门", "index": 3 },
    { "order": "SO-1002", "part": "柜门", "index": 2 }
  ]
}
```

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "original": { "boardsCount": 2, "totalMaterialCents": 36000, "...": "同 /api/cut，原样不变" },
    "recut": {
      "damagedCount": 3,
      "maxCutLength": 800,
      "addedBoards": 1,
      "addedMaterialCents": 18000,
      "items": [
        { "order": "SO-1001", "part": "柜门", "index": 1,
          "srcBoard": 1, "board": 1, "x": 0, "y": 0, "w": 600, "h": 400, "rotated": false },
        { "order": "SO-1001", "part": "柜门", "index": 3, "srcBoard": 1, "board": 1, "...": "..." },
        { "order": "SO-1002", "part": "柜门", "index": 2, "srcBoard": 2, "board": 1, "...": "..." }
      ],
      "orders": [
        { "order": "SO-1001", "partsCount": 2, "materialCents": 12000, "boardIndices": [1] }
      ],
      "boards": [
        { "index": 1,
          "placements": [{ "order": "SO-1001", "part": "柜门", "index": 1, "srcBoard": 1, "...": "..." }],
          "cuts": [{ "seq": 1, "type": "v", "...": "..." }],
          "cost": { "priceCents": 18000, "shares": ["..."] } }
      ]
    }
  }
}
```

- `original`：以当前输入重算的原方案，结构同 `/api/cut`（含 `remnants` 已用 / 未用
  与逐板 `kind` / 实际尺寸），落位与分摊不受补切影响。
- `recut.items[]`：补切清单，`srcBoard` 为原板号（原方案中可能是余板）、
  `board` 为补切新板号（均为标准新板）；
  按新板号升序、同板按原输入顺序（订单 → 零件行 → 件号）排列。
- `recut.addedBoards` / `recut.addedMaterialCents`：新增**标准**板数与新增材料费
  （分，= 新增标准板数 × 单板价；补切不产生余板）。
- `recut.maxCutLength` / `recut.boards[].longestCut`：补切排料所用单刀上限
  （未设置为 `null`）与每张补切板实际最长刀长，含义同 `/api/cut`。
- `recut.boards[]`：补切标准新板的落位（含 `srcBoard`，`kind` 均为 `standard`）、
  刀序与逐板分摊，结构同原方案。
- 所选件不存在、重复选择、补切超刀长或输入非法时返回 HTTP 400 与
  `{ "ok": false, "error": "..." }`。
